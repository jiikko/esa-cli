# 017 (retro): esa sync の差分の色付け〜v0.4.2 のリリース

起票日: 2026-10-06

## 踏んだところ

1. **`go get <依存>@latest` が go.mod の `go` 行を黙って上げた**（golang.org/x/term の最新が go 1.26 を要求し、
   `go 1.25.0 => 1.26.0`）。出力に 1 行出ただけで rc=0。CI は `go-version-file: go.mod` なので、そのまま
   commit すると CI と Homebrew のビルド環境の版が変わっていた。既に依存グラフにある版（v0.44.0）を明示して避けた。
2. **初版のテストは「色が付かないこと」しか見ていなかった**。端末の判定が壊れて二度と色が出なくなっても緑のまま。
   red team の素通り観点が見つけ、pty を開くテストで閉じた。
3. 疎通確認で `esa search 'README' -no-header`（フラグをクエリの後ろに置いた）と、既定の列に URL が無いのに
   `meta -copy` へ渡す取り違えを 1 回ずつした。どちらも CLI が明示的なエラーを返したので実害なし（局所的。改善案なし）。

## 提案

- **項目 1（一般形）**: 依存を足す・上げるときは、`go.mod` の `go` / `toolchain` 行（他の言語なら engines・
  required_ruby_version 等の処理系の版の要求）が差分に入っていないかを、commit の前に `git diff go.mod` で見る。
  処理系の版を CI と配布先が go.mod から決める repo では、依存の追加が処理系の版の引き上げを兼ねてしまう。
  切り出し先: `_claude/rules/verify-execution-not-just-exit-code.md` の「手元と CI で toolchain の版が違うなら」節への 1 行の追記を提案。
- **項目 2（一般形）**: 出力を「条件によって変える」機能（色・TTY 判定・ロケール・詳細度）は、
  変えない側だけでなく**変える側が実際に起きることを確かめるテスト**を最初から置く。抑止側だけのテストは、
  機能そのものが消える退行を素通しする。切り出し先: `mutation-verify-new-tests.md` の
  チェックリスト（`rules-checklists/`）の「到達しているか」へ 1 行の追記を提案。
- 項目 3: 却下（その CLI の使い方の取り違えで、エラーが即座に出た。一般化する価値なし）。

## 残課題

- 項目 1・2 の切り出しはユーザーの判断待ち。
