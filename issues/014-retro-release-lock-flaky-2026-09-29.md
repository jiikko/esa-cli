## どこで踏んだか / 次に効きそうな改善

1. **同一性の鍵を置き換えたら、旧い鍵が守っていた同値を落とした**
   - `--apply` の排他の鍵を「パスの文字列」から「シンボリックリンクを解決した実パス」に置き換えた。
     敵対的レビューが、ロックを取った後にリンクが指し直されると同じ文字列の 2 本が取れる退行を再現した
     （旧い鍵では必ず排他だった）。最終的には鍵を両方取る形にした
   - 一般形: 判定の鍵（同一性・キャッシュのキー・重複の判定）を別の鍵へ置き換えるときは、旧い鍵で同じとされていた組を
     列挙し、新しい鍵がその全部を同じと判定するかを確かめる。確かめられないなら、置き換えずに両方で判定する
   - 切り出し先: `_claude/rules/list-masked-failure-modes-before-removing-guard.md` へ追記（「置換で既存の hook が消えるときも
     同じ」の隣。ガードを外すのと同じく、旧い鍵が副次的に守っていたものを落とす形）

2. **手元の Go の版と CI の Go の版が違い、CI でだけ落ちる不具合を push してから知った**
   - 手元は go1.26、CI は `setup-go` が go.mod の `go 1.25.0` をそのまま入れる。chromecookie の `DirEntry.Info()` が
     go1.25.0 でだけ失敗する不具合（dotfiles の commit「fix(chromecookie): 残骸の古さを Root 起点の Lstat で判定する」）は、
     CI が赤くなって初めて分かった。以後は `GOTOOLCHAIN=go1.25.0 go test` を push 前に回して防げた
   - 一般形: CI が go.mod・`.tool-versions` 等から版を決める repo では、push の前に CI と同じ版でもテストを 1 回回す
   - 切り出し先: `_claude/rules/verify-execution-not-just-exit-code.md` の「実行環境を変えたら、変更前後の出力を全行 diff する」
     の節へ追記（「手元と CI で toolchain が違うなら CI の版でも回す」）

3. **長い背景のレビュー（codex）を、上限を決めずに待った**
   - codex の敵対的レビューが 40 分かかり、その間の報告が無く、ユーザーに「スタックしていない？」と聞かれた
   - 一般形: 背景の長い作業を待つときは、待ち始めに「いつまで待つか・超えたらどうするか」を決めて伝える
   - 切り出し先: `_claude/rules/verify-execution-not-just-exit-code.md` の「待つと決めたら待つ」の項へ追記

4. **リリースの版を決める前に、他のセッションが出した tag を見ていなかった**
   - v0.1.8 の後に別のセッションが v0.2.0 / v0.3.0 を出していた。v0.3.1 を打つ直前に tag を取り直して気づいた
   - 一般形ではなく、この repo の手順の話。README の「リリース」節の 1 に「`git fetch --tags` で最新の版を確かめてから
     版を決める」を足せば閉じる（slack-cli / newrelic-nrql-cli の同じ節も同じ）
   - 切り出し先: 3 repo の README の「リリース」節へ追記
