# 015 (feat): 書き出し先の指定に `skip` を足し、同期の対象から外す記事を作れるようにする

起票日: 2026-09-30

## 概要

`esa sync` はカテゴリ配下の記事を**すべて**書き出す。esa の上だけで読む記事（そのカテゴリの skill の説明・索引など）を
同じカテゴリに置くと、記事名のパス（`README` → `<dir>/README.md`）へ書き出され、そこにある別のファイルを上書きする。

実例（2026-09-30）: カテゴリ `Users/jiikko/local` → ubiregi-server の checkout のルートの対象に、
esa の上の説明の記事 `README`（WIP）を置いたところ、dry-run に「git 管理下の `README.md`（153 行）をその記事の 1 行で置き換える」差分が出た。
記事は esa の上で育てたいので消せず、今は `--apply` を打てない（他の記事の反映も止まる）。
書き出し先の指定（issue 010 / 013）は「どこへ書くか」しか選べず、「書かない」を選べない。

## 仕様

- 書き出し先の指定の値に、パスの代わりに `skip` を書ける。書き方は 010 / 013 と同じ 2 通り（両方あればエラー、は今どおり）:
  - 本文の最後の行: `<!-- esa-sync: skip -->`
  - skill の front matter: `metadata:` の下に `esa-sync: skip`
- `skip` の記事は**書き出さない**。記事名・本文のパスの検査も、他の記事との衝突の検査もしない（書かないので衝突しない。記事名に `/` があってもよい）
- カテゴリの判定は今どおり先に行う（対象の外の記事は、`skip` があっても今どおり除く）
- 🚨 **黙って飛ばさない**。dry-run と `--apply` の出力に、記事ごとに
  `  - <カテゴリ>/<記事名>  書き出さない esa #N（本文の指定 esa-sync: skip）` を出し、件数の行に ` / 書き出さない K` を足す（K>0 のとき）。
  書き込み（予定）の件数（「dry-run です」の案内の判定）には数えない
- 記事名のパスに既にあるローカルのファイルには触らない（消さない・書かない）。「esa で消した記事のファイルは消さない」と同じ扱い
- 値は小文字の `skip` ちょうどだけ。`Skip` / `SKIP` / `skip.md` 以外の `.md` で終わらない値は今どおりエラー（`.md` で終えてください）にし、
  エラーの文言で `skip` を案内する
- 🚨 **崩れた `skip` を黙って記事名の規則に戻さない**（戻すと、書かないつもりの記事が書き出され、実例のように別のファイルを上書きする。
  `.md` の指定の崩れより被害の向きが悪い）。崩れの検出（010 の `syncDirectiveLooseRe`、013 の YAML のキーの検査と `firstSyncKeyLine`）は、
  今「コロンの後に `.md` のパス」を条件にしているので、`skip` にも当たるように広げる:
  - コメント: `<!-- esa-sync:skip -->`（空白なし）・`<!-- ESA-SYNC: skip -->`・`<!-- esa_sync: skip -->`・全角のコロン など → エラー
  - front matter: 最上位の `esa-sync: skip`・`metadata.esa_sync: skip` → エラー。`metadata.esa-sync: false`（文字列でない）は今どおりエラー
  - 読めない・閉じの無い front matter の中の `esa-sync: skip` の行 → エラー
  - 誤検出を増やさない（反証レビュー P1）: `.md` のパスは説明の文にほとんど出ないが、`skip` は普通の語として出る。
    そこで `skip` の崩れは、**行が指定だけでできているとき**に限って拾う（行の前後に許すのは空白・コメントの記号 `<!` `-->` `—>`・
    コードや強調の記法 `` ` `` `*` `_` だけ）。「…と書くと esa-sync: skip という指定になり…」のような説明の文・`# esa-sync: skip を使う` の見出し・
    `skipping` は止めない
  - front matter の YAML として読めるときは、キーが `esasync` 相当で値がちょうど `skip`（大文字小文字を問わない）のものだけを拾う（値の文から拾わない）
- 検出しない形（010 / 013 と同じく、書き損じは dry-run の書き出し先で気づく）: `skip` の綴りの崩れ（`skp`・`sk1p`）・`esa` と `sync` の文字を似た別の文字に置き換えたもの

## 対応方針

- `mapSyncFiles` で `findSyncDirective` の**直後**（`syncDirectiveRelPath`・衝突の検査より前）に分岐し、`skip` ならファイルにせず「書き出さない記事」として返す
  （後ろで分岐すると、空のパスで衝突の検査に入り、`skip` の記事が 2 件あると誤って衝突になる。反証レビュー P2）
- `syncDirectiveRelPath` の「`.md` で終えてください」のエラーに `skip` の案内を足す（反証レビュー P3）
- `syncPlan` に書き出さない記事を持たせ、`printSyncPlan` が出す
- 崩れた `skip` の検出を 1 つの関数に置き、コメントの検出（`looksLikeSyncDirective`）と、読めない front matter の検出（`firstSyncKeyLine`）の両方から呼ぶ。
  YAML として読める front matter（`extractFrontMatterDirective` の problems）は値がちょうど `skip` かで見る
- help（`syncHelp`）と README の「書き出し先の指定」に `skip` を足す

## 受け入れ条件

- [x] `<!-- esa-sync: skip -->` / `metadata.esa-sync: skip` の記事は書き出されず、ローカルの同じ名前のファイルは変わらない
- [x] dry-run と `--apply` の出力に、書き出さない記事の行と件数が出る。書き出さない記事だけの対象では「dry-run です」を出さない
- [x] 崩れた `skip`（上の例）はエラーになり、その対象は 1 件も書かない
- [x] `skipping` のような語・`esa-sync: skip` を含む説明の文・見出しは止めない
- [x] help と README に書いた
- [x] 新しいテストは変異を当てて red を確認した

| 指摘 | 採否 | 対応 |
|---|---|---|
| ① P1 1 行にまとめた `metadata: esa-sync: skip`・閉じ忘れのフロー形式 `metadata: {esa-sync: skip` が黙って書き出される（`.md` なら止まる） | 採用（再現） | 読めない front matter では「esa〜sync のキーの値がちょうど skip」で拾う（`syncKeyLineIsSkip`。キーの前は問わない） |
| ① P2 本文の途中の `<!-- esa-sync: skip -->` が黙って無視される | 採用（再現） | 最後の行が skip でないのに、厳密な skip の行が本文の途中にあればエラー（`syncStraySkipLine`。コードブロックの中は見ない） |
| ① P3 番号付きの項目の中のコメント `1. <!-- esa-sync: skip -->` | 採用 | 箇条書きの項目は、中身がコメントで始まるときだけ崩れとして見る |
| ① P3 `<!--esa-sync: skip。-->`・`metadata:\n  esa-sync:skip` | 注意で拾う | 字面では閉じないので、結果の側の注意（下）で知らせる |
| ① P3 表示が「本文の指定」と出る（front matter でも）・skip の行の並びが検索順 | 採用 | 「書き出し先の指定」に変え、記事番号の順に並べる |
| ② P2 使い方の例（`` `<!-- esa-sync: skip -->` ``）の直後に本物の指定を書くと「2 つある」で止まる | 採用 | 最後の行が skip なら、skip らしい行とは意味が食い違わないので止めない |
| ② P2 `- esa-sync: skip` などの箇条書きを指定の崩れとして止める（README の記述とも食い違う） | 採用 | 箇条書きの項目は拾わない（上の ① P3 と両立する形） |
| ② P3 全部 skip のときの「カテゴリが一致しない」の注意の条件がテストされていない | 採用 | テストを足した（条件を戻す変異で red を確認） |
| ② P3 崩れた skip のエラーがパスの書き方を案内する | 採用 | skip の形を案内する |
| ② P3 `---` の水平線で始まり空行までに `esa-sync: skip` の行がある記事が止まる | 記録のみ | `.md` の指定にも前からある形で、現実には稀 |
| ② P3 例の行を 1 行目に置くと「先頭にあります」で止まる | 記録のみ | 止まる向き（書き出さない側）で、1 行目に例を置く記事は稀 |

**字面の検出の限界と、結果の側の注意**: 崩れた skip は、1 つ塞ぐたびに別の崩し方が出た（1 行の metadata・本文の途中・番号付きの項目）。
013 と同じく、軸を結果へ移して最後の砦にした: 書き出す記事の本文に「esa〜sync … skip」の行があれば、dry-run と `--apply` に毎回「注意:」を出す
（`syncSkipIntentWarning`。エラーにはしない。skip の使い方を説明する記事も書き出せるように）。

検出しない形（注意も出ない）: `skip` の綴りの崩れ・`esa` と `sync` の文字を似た別の文字に置き換えたもの。
注意だけで止めない形（エラーにならず、出力の「注意:」で気づく）: 読めない front matter の `esa-sync: skip # コメント`・front matter の中の `---` で
2 つ目の YAML 文書に落ちた metadata（`.md` の指定と共通）・複数行に分けたコメント `<!-- esa-sync:\nskip -->`（010 から字面では検出しない形）。
