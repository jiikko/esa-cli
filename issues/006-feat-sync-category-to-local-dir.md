# 006 feat: カテゴリ配下の記事をローカルのディレクトリへ書き出す `esa sync`

起票日: 2026-09-29

## 概要

esa のカテゴリ配下の記事を、ローカルのディレクトリへ Markdown のファイルとして書き出す（esa → ローカルの一方向）。
会社・チームに依存する Claude Code の skill / rule を esa で管理し、手元へ配る用途。特定のチームには依存させない。

## 仕様

- 対象の定義は `sync.yml`（`config.yml` と同じディレクトリ。`name` / `category` / `dir` の 3 項目だけ）
  - `config.yml` と分けた理由: `saveFileConfig` が struct から組み立て直して書き戻すため、手で書いたコメントや未知のキーが消える
- `esa sync add`: 対話式で追加（カテゴリは `https://<team>.esa.io/#path=...` の URL も可）。保存前にカテゴリ配下の件数を esa に問い合わせて表示
- `esa sync [名前...]`: 既定は dry-run（新規・変更・差分）。`--apply` で書き込む
- `esa sync list`: 登録済みの一覧
- 対応: `<category>/a/b` の記事 `SKILL` → `<dir>/a/b/SKILL.md`（`.md` で終わる名前はそのまま）。本文のみ・改行は LF。WIP も対象
- 書かないもの: esa で消した記事のファイルの削除はしない（ユーザーの指定: 「ディレクトリのみをローカルに書くだけでいい」）

## 設計の判断

- 記事の一覧は検索 HTML のページ送り。**終端は pagination の `rel="next"` の有無で判定する**
  （2026-09-29 に実測: sort なしで最後より先を要求すると 1 ページ目が返り、`sort:number-asc` ありだと
  「0 件」の目印の無い空ページが返る。どちらも最後のページには `rel="next"` が無い）。
  保険として「新しい番号が 1 件も無いページ」でも止め、200 ページで打ち切ったら切り詰めずにエラー
- `in:` は前方一致なので、`Users/me/skills2` のような隣のカテゴリは記事 JSON の category で除く
- 1 対象は計画（一覧・取得・対応付け・書き出し先の検査）を全部終えてから書き始め、1 件でも問題があれば 1 件も書かない
- 書き込みは `os.Root` 経由（dir の外・リンク越しには書けない）。書き出し先がリンク・ディレクトリなら拒否。
  一時ファイル + rename で置き換え、既存ファイルの権限は保つ
- 削除の機構を持たないので、ローカルの残骸の掃除は無い（adversarial-review §0-A: 破壊的操作を新設しない）

## レビューの結果（read-only のサブエージェント・観点別に直列で 3 周）

1 周目（壊す）: dir の外への書き込みは壊せなかった。以下を採用して直した
- 大文字小文字・NFC/NFD だけ違う 2 記事が同じファイルになり片方が消える → パスの鍵（`syncPathKey`）で衝突を検査
- 2000 行を超えると差分を行数だけにして手編集が dry-run に出ない → `largeDiffSummary` で違う範囲の先頭・末尾を出す
- ファイルとディレクトリの衝突で途中まで書く / dir 内の相対リンクで別記事のディレクトリへ書く → 計画の段階で拒否
- ページ送りの途中で記事が抜けると一覧が欠ける → 2 回続けて同じ一覧になるまで取り直す（最大 4 回）
- 制御文字で dry-run の表示を偽装できる → `visible` でエスケープ
- sync.yml のリンクを通常ファイルに置き換える / 複数文書の 2 つ目が消える / dir の重なり / 一時ファイル名 → それぞれ拒否・実体へ書く
- 計画から書き込みまでの手編集 → rename の直前に読み直して一致しなければ書かない。fsync を追加

2 周目（素通り・回帰。1 周目の修正への攻撃）: 既存コマンドの回帰と go.mod（配布への影響）は見つからなかった
- `ToLower` の鍵は ß/ss・σ/ς 等で APFS とずれる → `cases.Fold` + NFC に
- `visible` がタグ文字・ゼロ幅・異体字セレクタ・埋め字を通す → 書式文字（Cf）等を追加
- 新規ファイルの本文が dry-run に出ない → 空からの差分として出す
- 大文字の一時ファイル接尾辞・末尾の `---` の過剰な拒否・コメントだけの sync.yml のコメント消失・エラー文のエスケープ漏れ → 直した

3 周目（2 周目の修正への攻撃）: `isEmptyYAMLDoc` とコメントの保持は 16 形 + 11 形で壊せなかった
- 新規の本文が上限なしで全行出る → 先頭と末尾の各 150 行
- Default_Ignorable の文字が素通り → `Other_Default_Ignorable_Code_Point` を追加
- Cherokee だけ鍵が APFS とずれる（172 組）→ 畳んだ後に大文字へそろえる。
  **実測**: SimpleFold の同値類・大小文字・NFC/NFD の候補 15,623 組を APFS で作って照合し、ずれ 0 組
  （canary: 旧い鍵では Cherokee の 172 組すべてがずれた）
- 3 周目の修正は各項目を直接の実測（APFS 照合・変異）で確かめたので、4 周目は回していない

### 受容したリスク（直さない）
- 大文字小文字を区別するボリュームでは、別の dir / ファイルを同じとみなして拒否する（安全側に倒れる）
- 絵文字の FE0F / ZWJ も表示ではエスケープされる（隠し込みの異体字セレクタと見分けられない。ファイルの中身は変えない）
- `esa sync add` の同時実行はロックしない（対話操作で、後に書いた方が勝つ）
- 置き換えで xattr・ACL・所有者は保たない（権限だけ保つ）
- `--apply` は、その時点の esa の内容を書く（dry-run の後に esa 側が変われば、変わった内容を書く。書く前に差分は出す）
- 大きい差分・長い新規本文は先頭と末尾だけを出す（違う行の範囲と省いた行数は必ず出す）
