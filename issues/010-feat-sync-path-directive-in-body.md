# 010 feat: 記事の本文に書き出し先のパスを書けるようにする（記事名を人が読める題にしたまま sync する）

起票日: 2026-09-29

## 概要

`esa sync` の書き出し先は「カテゴリ/記事名」で決まる（`<category>/foo/SKILL` → `<dir>/foo/SKILL.md`）。
Claude Code の skill を esa で管理すると、記事名を `SKILL` にしないと `SKILL.md` に書き出されない。esa の一覧・検索で、どの記事か読めなくなる。

記事の本文に書き出し先のパスを書けるようにし、書いてある記事はその指定に従う。記事名は人が読める題（例: `月次 New Relic 監査: 速度ボトルネックとエラーレポート作成(ubiregi-server編)`）のままにできる。
ファイル名と記事名は 1:1 でなくなるが、sync で同期する前提なので困らない（ユーザーの判断）。

## 背景

- 実例: ubiregiinc の記事 #33021（カテゴリ `Users/jiikko/local/.claude/skills`、記事名は上の題）。今の規則では `<dir>/月次 New Relic 監査: ….md` という 1 ファイルになり、skill として読まれない。
- esa の記事には自由に使えるメタデータの欄が無い（タイトル・カテゴリ・タグ・本文だけ）。置き場所は本文かタグになる。

## 仕様（反証レビュー後の確定版）

### 指定の書き方

本文の**最後の空でない行**に、次の形の HTML コメントを 1 行だけ書く（厳密な形。空白は ASCII のスペース 1 つずつ）。

```
<!-- esa-sync: nr-monthly-audit/SKILL.md -->
```

- 本文の**先頭には置かない**。Claude Code の `SKILL.md` は 1 行目が front matter の `---` でないと読まれないので、指定は末尾にする。
- esa の画面では HTML コメントは表示されないはず（**未確認**。実装前に #33021 で目視する）。

### パスの基準: 記事のカテゴリに対応するディレクトリからの相対

- 指定のパスは、**その記事のカテゴリに対応するディレクトリ**（今の規則で記事名のファイルが置かれるディレクトリ）からの相対にする。対象の `dir` からの相対にはしない。
  - 例: 対象の category が `Users/me/skills`、dir が `X` のとき、カテゴリ `Users/me/skills` の記事の `nr-monthly-audit/SKILL.md` は `X/nr-monthly-audit/SKILL.md`。カテゴリ `Users/me/skills/team` の記事なら `X/team/nr-monthly-audit/SKILL.md`。
  - 理由（red team の P2-1）: `validateSyncTargets` は dir の入れ子だけを止め、category の入れ子は通す。dir 相対にすると、下位カテゴリの記事が上位の対象の最上位を狙えて、**今の規則より書ける範囲が広がる**。カテゴリ相対なら、記事が書けるディレクトリは今の規則と同じ（記事名の代わりに、その下の相対パスを選べるだけ）。
- 指定のある記事では、**記事名を書き出し先に使わない**。記事名の検査（`/` の禁止・`.md` の付与・長さ）もしない（事実レビューの P1: 人が読める題には `/` が普通に入る。検査を残すと、指定があっても対象全体が止まる）。
- 指定の無い記事は、今の「カテゴリ/記事名」の規則のまま（**既存の記事の書き出し先は変わらない**）。
- 対象のカテゴリの外の記事は、指定があっても今どおり除外する（カテゴリの判定は記事名・指定と独立に先に行う）。

### 指定のパスの検査

- `syncRelPath` を 3 つに分ける（事実レビューの P1）:
  1. カテゴリの判定（対象の配下か・配下のパスの要素）
  2. 記事名 → ファイル名（`/` の禁止・`.md` の付与。指定の無い記事だけ）
  3. 要素ごとの検査（空・`.`・`..`・NUL・一時ファイルの接尾辞・UTF-16 で 255 の上限。**指定のパスもこれを通す**。検査を 2 つ書かない）
- 指定のパスに固有の検査:
  - `.md` で終わる（大文字小文字は今の規則と同じく区別しない）
  - 絶対パス（`/` 始まり）・`\`・`--`（HTML のコメントとして不正。red team の P2-6）を拒否
    （2026-09-29 追記: `--` の拒否はこのコメントの指定だけに掛かる。issue 013 の front matter の指定では通す）
  - 要素の前後に Unicode の White_Space がある・要素が Cf / Default_Ignorable の文字を含むなら拒否（NBSP などで見分けにくい別のディレクトリを作らせない。red team の P2-4）
  - HTML エンティティ・URL として復号しない（書いたバイト列のまま）
- 衝突の検査（`mapSyncFiles` の `owner` と `syncPathKey`）: 指定のパスと、他の記事の指定のパス・今の規則のパスは、同じ鍵の空間で突き合わせる。ファイルとディレクトリの衝突も同じ。**衝突のエラー文に、どちらが指定によるものかを出す**（複製した記事で指定が写ったとき、「記事名を変えてください」は直し方として誤りになる。red team の P2-8）。
- 違反が 1 件でもあれば、今どおりその対象は 1 件も書かない。

### 指定の行の見つけ方（取り違えない・黙って落とさない）

順序を固定する（red team の P2-10）:

1. 本文を今どおり正規化する（`normalizeSyncBody`: CRLF → LF）。
2. 「空の行」= Unicode の White_Space・Cf・Default_Ignorable の文字だけからなる行（空文字列を含む）。末尾の空の行を飛ばして、**最後の空でない行**を候補にする（red team の P2-3: U+200B だけの行の後ろに指定があっても見つける）。
3. 候補の行を**加工せずに**厳密な形 `<!-- esa-sync: <パス> -->` と照合する（行頭の空白は許さない。先頭を削ると、字下げのコード例を指定として食う。red team の P2-5）。
4. 一致しないとき、候補の行を NFKC にそろえ、見えない文字を除き、小文字にした形が「`esa`・区切り・`sync`・記号・コロン・`.md` で終わるパス」の並び（`syncDirectiveLooseRe`）を含むなら**エラー**（崩れた指定）。含まなければ「指定なし」。
   - 実装の red team を 3 周して決めた形。コメントの記号で限ると em dash の `<!— … —>` や包み忘れを見逃し、コロンやパスを要件にしないと「esa sync: カテゴリを同期する」のような説明の文で対象全体が止まった。
   - **この判定は書き損じに気づかせる補助で、安全の砦ではない**。指定が効かなかった記事は、dry-run に記事名のパスの新規ファイルとして出る（「書き出し先は本文の指定による」が付かない）。優先するのは誤検出で対象を止めないこと。
   - 検出しない形（コードのコメントが正本）: 似た別の文字・コロンやパスを落としたもの・`.md` で終わらないパス・複数行に分けたもの・指定の後ろへの追記で本文の途中に押し出されたもの。
4'. **最初の空でない行**が指定らしい（4 の判定）のに最後の行でないなら、エラー（skill の front matter の上に書く間違いが一番起きやすい）。
5. 一致したら、その行と、それより後ろの空の行を取り除く。**取り除いた後の最後の空でない行が、また指定の形（4 の判定に当たる）ならエラー**（指定が 2 つ。red team の P2-7）。
6. 書き出す本文 = 指定の行と、その直前に続く空の行（2 の定義）を落とし、改行 1 つで終える（空なら空）。
- 本文の途中（閉じたコードブロックの中・説明の文中）にある同じ形の文字列は、候補にならないので触らない。

### dry-run の表示

- 指定による書き出し先には「（書き出し先は本文の指定による）」を付ける。記事の番号は今も出ている（`esa #N`）。URL は出さない（番号で辿れる）。

### 対応表は作らない（今回）

- `dir` に対応表（`.esa-sync.json` など）を書く案は採らない。書き込みの新設になり、名前の予約・計画とロックへの載せ替えが要る（red team の P2-9）。dry-run / `--apply` の出力に番号と URL を出すことで代える。

## 考慮した点

- **書ける範囲は今と同じ**（カテゴリ相対にしたため）。今も、記事を編集できる人は記事名を変えて、そのカテゴリのディレクトリの中の任意の `.md`（手で置いた esa 以外のファイルを含む）に書き出し先を向けられる。指定も同じ範囲の中で相対パスを選べるだけで、`dir` の外へは出られない（red team は dir の外への書き込みを壊せなかった）。
- **見えやすさは今より悪い**（red team の評価）。今は書き出し先を変えると、esa のカテゴリの一覧・記事名に現れる。指定は描画された画面に出ない。dry-run の「（指定による）」の表示で、手元での確認には効くが、esa 側でのレビューのすり抜けは減らない。受容する（書き込む前に dry-run を見る運用が前提。`--apply` は今も確認なしで書く）。
- **改名に強くなる**: 記事名を変えても、指定があれば書き出し先は変わらない。今は記事名を変えると別のファイルに書かれ、古いファイルが残る（006 の「受容したリスク」）。
- **指定を変えたときの古いファイルは残る**: 今の改名と同じ扱い（sync は消さない。006 の方針）。dry-run に出ないのも同じ。
- タグに置く案は採らない: esa のタグに `/` や `.` が使えるか未確認で、一覧で目に入る。
- skill の front matter に独自のキーを足す案は採らない: skill 以外の記事で使えず、Claude Code が知らないキーを無視するかも未確認。

## 未確認の関連事項

  sync が使う `body_md` の先頭にも空行があると、書き出した `SKILL.md` の 1 行目が空になり、skill として読まれない可能性がある。実装の前に `esa sync` の dry-run で #33021 を出し、先頭の行を確かめる。空行があるなら、先頭の空行の扱いを本 issue か別の issue で決める。

## テスト

- `mapSyncFiles` を直接呼ぶ表駆動テストを**新設する**（今は `fakeEsa` 経由の統合テストからしか通っていない。事実レビューの P2）。`TestSyncRelPath` の形にならう。ケース:
  - 指定あり → 指定のパス・本文から指定の行が消えている
  - 指定なし → 今の規則のまま
  - 指定のパスが `..` / 絶対パス / `.md` 以外 / 長すぎる / `--` を含む / NBSP で始まる → 対象ごとエラー
  - 指定どうし・指定と今の規則が同じ鍵（大文字小文字・NFD）→ 衝突エラー（エラー文に「指定による」）
  - 記事名に `/` がある記事に指定がある → 通る（記事名は使わない）
  - 下位カテゴリの記事の指定 → そのカテゴリのディレクトリの下に書かれる
  - 指定の形の文字列が本文の途中やコードブロックにある → 指定とみなさない・取り除かない
  - 最後の行が崩れた指定（全角のコロン・大文字・`<!--esa-sync:`・ゼロ幅の文字・引用・字下げ）→ エラー
  - 指定の後ろに U+200B だけの行 → 指定として見つかる
  - 指定が 2 行続く → エラー
  - 取り除いた後の本文の末尾（`text\n\n<!-- … -->\n` → `text\n`）
- 変異検証: 指定のパスの検査を外す、または衝突の鍵を指定の分だけ別にすると赤くなることを確かめる。
- ヘルプ（`syncHelp`）の「対応の規則」に 1 行足す。README の sync の節にも足す。
